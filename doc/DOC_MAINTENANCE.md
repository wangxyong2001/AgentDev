> 版本: v1.0 | 创建日期: 2026-06-20

---

## 1. 文档体系

```
doc/
├── BRD.md                 # 业务需求文档 (做什么)
├── FSD.md                 # 功能规格文档 (怎么做)
├── ISSUE_TRACKING.md      # 问题追踪清单 (Bug/架构债务)
├── GLOSSARY.md            # 术语表 (技术概念定义)
└── DOC_MAINTENANCE.md     # 本文档 (如何维护)
```

### 文档关系

```
需求变更/新需求
      │
      ▼
   BRD.md  ◄── 业务需求层 (BR-xxx)
      │
      ▼
   FSD.md  ◄── 功能规格层 (组件/接口/数据流)
      │                              │
      ▼                              ▼
   源码     ◄── 实现层        GLOSSARY.md ◄── 术语定义 (技术概念)
      │
      ▼
   ISSUE_TRACKING.md ◄── 问题追踪 (BUG-xxx / ARC-xxx)
```

## 2. 触发条件

以下情况必须更新对应文档：

### 2.1 BRD 更新触发条件

| 变更类型 | 示例 | 更新动作 |
|---------|------|---------|
| 新增业务需求 | 添加新工具类型、支持多 Agent | 新增 `BR-xxx` 条目 |
| 修改功能边界 | 上下文窗口从 4K → 8K | 更新对应 BR 的验收标准 |
| 新增非功能性需求 | 添加延迟 SLA 要求 | 新增 `NFR-xxx` 条目 |
| 修改目标用户 | 新增 "运维/SRE" 角色 | 更新 §2.3 用户角色 |
| 外部约束变化 | Jetson 升级到下一代 | 更新 §5.1 技术约束 |

### 2.2 FSD 更新触发条件

| 变更类型 | 示例 | 更新动作 |
|---------|------|---------|
| 新增组件/模块 | 提取 `LlmAdapter` 类 | 新增 §3.x 组件规格 |
| 接口变化 | 函数签名变更、新增参数 | 更新对应组件的接口定义 |
| 数据流变化 | 新增中间处理步骤 | 更新 §4 数据流图 |
| 配置参数变化 | 新增/修改默认值 | 更新 §5 配置参数表 |
| 错误处理变化 | 新增错误类型 | 更新 §6 错误处理矩阵 |
| 新增已知限制 | 发现新的边界条件 | 更新 §7 已知限制 |

### 2.3 GLOSSARY 更新触发条件

| 变更类型 | 示例 | 更新动作 |
|---------|------|---------|
| 新增技术概念 | 引入新算法/协议 | 新增术语条目 |
| 概念定义变化 | 量化级别升级 | 更新对应条目 |
| 新读者需要解释 | 用户反馈术语不理解 | 补充解释和示例 |

### 2.4 ISSUE_TRACKING 更新触发条件

| 变更类型 | 示例 | 更新动作 |
|---------|------|---------|
| 发现新 Bug | 运行时异常 | 新增 `BUG-xxx` |
| 发现新架构问题 | Code review 发现耦合 | 新增 `ARC-xxx` |
| Bug 修复 | 代码已合并 | 更新状态 → ✅ 已修复 |
| 架构重构完成 | 模块提取完成 | 更新状态 → ✅ 已完成 |
| 新增预防措施 | CI 规则上线 | 更新对应条目的预防措施 |

## 3. 更新流程

### 3.1 功能性修正

```
1. 在 ISSUE_TRACKING.md 记录问题 (如 ARC-xxx)
       │
2. 评估是否需要修改 BRD  (业务需求是否变化?)
       │
3. 修改 FSD 对应组件规格
       │
4. 修改源码
       │
5. 验证: 源码行为与 FSD 描述一致
       │
6. 更新 ISSUE_TRACKING.md 状态
       │
7. 更新各文档的版本历史表
```

### 3.2 新需求

```
1. 在 BRD.md 新增 BR-xxx 条目
       │
2. 在 FSD.md 新增组件规格/数据流
       │
3. 实现源码
       │
4. 验证: 源码与 BRD 验收标准一致
       │
5. 更新 ISSUE_TRACKING.md (如有实现过程中的已知限制)
```

### 3.3 文档版本号规则

```
BRD/FSD 版本号: v<major>.<minor>
  major: 新增或移除 BR/组件     → v1.0 → v2.0
  minor: 修改 BR/组件 内部细节   → v1.0 → v1.1

每次变更:
  1. 更新文档头部的 "最后更新" 日期
  2. 在 §版本历史 表追加一行
```

## 4. 文档一致性检查清单

每次 PR / 功能性变更后，逐项确认：

- [ ] BRD 中的 `BR-xxx` 是否仍覆盖所有已实现功能？
- [ ] FSD 中的组件接口是否与源码签名一致？
- [ ] FSD 中的数据流是否反映了当前实际流程？
- [ ] FSD 中的配置参数表是否与 `ReActProtocol.yaml` + 全局常量一致？
- [ ] ISSUE_TRACKING 中已修复的问题是否标记为 ✅？
- [ ] 所有文档的 "最后更新" 日期是否刷新？
- [ ] 新增的已知限制是否写入 FSD §7？
